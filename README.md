# QuickPizza API Lab — ITCS386

API testing exercise using Python, `requests`, and `pytest` against the public QuickPizza demo API.

## Run locally

Requires Python 3.10+.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
pytest -v --html=report.html --self-contained-html
```

The suite sends real HTTP requests. It requires internet access and may fail if QuickPizza is unavailable or its behavior changes. Do not run repeatedly in a loop. Each test uses a new account for writes; the public token is only used for read-only and recommendation examples.

## Input domain model — POST /api/ratings

| Characteristic | Block | Example | Covering test |
|---|---|---|---|
| C1 stars value | below 1 | 0 | `test_stars_out_of_range[0]` |
| C1 stars value | 1–5 (base) | 3 | `test_base_choice_is_saved` |
| C1 stars value | above 5 | 6 | `test_stars_out_of_range[6]` |
| C2 stars type | integer (base) | 3 | `test_base_choice_is_saved` |
| C2 stars type | decimal | 3.5 | `test_decimal_stars_refused` |
| C2 stars type | text | "3" | `test_text_stars_refused` |
| C2 stars type | missing | absent | `test_missing_stars_refused` |
| C3 pizza | exists (base) | generated id | `test_base_choice_is_saved` |
| C3 pizza | nonexistent | 999999999 | `test_unknown_pizza_refused` |
| C4 token | valid (base) | own login token | `test_base_choice_is_saved` |
| C4 token | absent | no header | `test_missing_token_refused` |
| C4 token | wrong length | short | `test_short_token_refused` |

Base choice changes one characteristic at a time from the valid base. Number of test cases: `1 + (3-1) + (4-1) + (2-1) + (3-1) = 9`. Full combinations: `3 × 4 × 2 × 3 = 72`.

## Files

- `conftest.py`: session and independent-user fixtures.
- `test_*.py`: positive, negative, boundary, ownership and defect tests.
- `RESULTS.md`: observations, defect report and reflection.
- `report.html`: generated by pytest-html after an actual run (not fabricated).

## Notes

Some API error messages in the student-written Part A tests are checked by their `error` field rather than exact text until they can be confirmed against the live service. See `RESULTS.md` for observations still requiring live verification.
